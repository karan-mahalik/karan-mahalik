## Problem and users

Describe the task, the allowed user role and how success will be measured.

## Boundaries

Record permitted datasets, forbidden personal/confidential content, privacy controls and restricted actions.

## Architecture

Describe inputs, preprocessing, prompts/retrieval, model version, validation, output and fallbacks.

## Reproducible demo

- [ ] Version-pinned dependencies
- [ ] Synthetic or public sample data
- [ ] No secret values in source control
- [ ] Setup, tests and screenshots from the real application
- [ ] Failure-mode documentation

## Evaluation

Include test questions, expected behaviors, attribution, accuracy, latency and safety results from **actual runs**.

## Release checklist

- [ ] Repository exists
- [ ] README explains limitations and known issues
- [ ] Runnable demo is independently inspected
- [ ] Profile card points to the real repository, not the planning index
